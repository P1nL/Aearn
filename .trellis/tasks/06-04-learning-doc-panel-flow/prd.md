# 学习页：添加文档面板和改进学习流程

## Goal

重新设计学习页的信息架构和交互流程，解决两个核心问题：
1. **学习流程生硬**：用户缺少系统性讲解和消化时间，直接被推入判断题
2. **UI 布局错误**：练习反馈消息显示在练习卡片上方

通过添加右侧文档面板承载完整知识点讲解，并调整学习流程为"阅读 → 主动提问 → 触发检验 → 练习"，提升学习体验。

## Current Blocking Finding: 复习侧栏误导用户进入空队列

### 用户反馈

用户完成第一个知识点学习后，左侧「复习」分组出现刚学习完的知识点；点击后进入复习页，但复习页显示「今日待复习」为空，提示「当前没有已到期复习项」。

### 已确认事实

- `aearn/apps/desktop/src/components/SidebarNav.tsx` 当前用 `knowledgePoint.status === "reviewing" || knowledgePoint.status === "mastered"` 构造左侧复习项。
- `aearn/apps/desktop/src/pages/ReviewPage.tsx` 当前用 `GET /api/reviews/today?user_id=...` 加载复习页队列，只展示后端返回的 `dueItems`。
- `aearn/services/api/app/services/repositories/review_repository.py` 的 `get_today_reviews()` 只返回 `review_states.due_at <= now()` 且未 suspend 的项。
- `POST /api/reviews/start` 会对未到期知识点返回 `REVIEW_NOT_DUE`，所以未到期知识点不能被直接开始复习。
- `review_scheduler.py` 在学习提交成功后会把下一次复习安排到未来时间：`Again` 为 10 分钟后，`Hard` 为次日 20:00，`Good` 为 3 天后 20:00，`Easy` 为 7 天后 20:00。
- 因此截图不是后端今日队列加载失败，而是左侧导航把「已安排复习的知识点」误展示成了「今日可复习的知识点」。

### 推荐产品语义

左侧「复习」分组可以展示已安排复习的知识点，但交互语义必须区分「已到期可复习」和「未到期仅预告」：

- 已到期项：可点击，进入复习页后必须能看到同一知识点并开始复习。
- 未到期项：可展示，但必须是禁用态，不触发页面跳转或 `POST /api/reviews/start`。
- 未到期项应有明确状态文案，例如「未到期」「下次 06-05 20:00」或同等提示，避免用户误以为当前可以复习。

复习页标题「今日待复习」仍只代表后端到期队列；左侧可以作为复习概览，但不能把未到期项做成可点击入口。

## Requirements

### 1. 文档面板（右侧栏）

#### 1.1 布局与显示
- 宽度：420px（固定或可调整）
- 位置：对话区右侧，与对话区并列
- 滚动：独立滚动容器，不影响对话区
- 显示时机：用户进入知识点后自动展开
- 可折叠：提供折叠按钮释放空间

#### 1.2 内容结构
文档包含以下标准章节：
- **核心概念**：2-3 段讲解，200-300 字，帮助建立心智模型
- **语法结构**：代码块 + 说明
- **实战示例**：2-3 个递进示例，从简单到复杂
- **常见错误**：3-5 个典型错误 + 正确做法对比
- **最佳实践**（可选）

每个章节包含：
- 标题
- Markdown 格式正文
- 代码块（如适用）：语言标识 + 代码 + 说明文字

#### 1.3 交互功能
- **目录导航**：顶部显示章节目录，点击跳转
- **章节折叠/展开**：
  - 默认展开：核心概念、语法结构、实战示例
  - 默认折叠：常见错误、最佳实践
  - 点击章节标题切换状态
- **文本选中引用**：
  - 用户在文档区选中文字（鼠标拖选）
  - 出现浮层提示："引用到对话"按钮
  - 点击后，对话输入框自动填充选中内容
- **代码块引用**：每个代码块底部显示"引用到对话"按钮

#### 1.4 内容生成（后端）
- **生成方式**：动态生成（LLM）
- **触发时机**：用户首次访问该知识点时
- **缓存策略**：Redis 缓存 24 小时，避免重复生成
- **API 端点**：`GET /api/learning-sessions/knowledge-points/{knowledge_point_id}/documentation?user_id=...`
- **生成输入**：
  - 知识点标题、描述
  - 所属模块、语言
  - （可选）官方文档链接
- **生成输出**：结构化 JSON，包含标题、摘要、章节数组、参考链接

### 2. 学习流程调整

#### 2.1 会话初始化改动
**当前行为（已按代码核对）**：
- 新学习会话直接写入 `session.learning_stage = "concept_check"`
- 自动生成并持久化 `show_concept_intro` 工具调用，立即显示概念判断卡片

**目标行为**：
- 推荐新增并使用 `session.learning_stage = "documentation_reading"`，但实现时必须同步更新 DB CHECK、后端/前端类型、API contract 和相关测试
- 如实现阶段选择兼容路径，可暂用现有允许的阶段并返回空 `initial_tool_calls`，但必须在设计、测试和 API 文档中明确没有真正新增 `documentation_reading`
- 发送引导性开场白（文本消息），不自动发送判断卡片
- 开场白内容：
  - 告知右侧有完整文档
  - 说明文档包含哪些内容
  - 引导如何提问：选中文字 → 引用到对话
  - 提示准备好后点击"开始概念检验"按钮

#### 2.2 概念检验触发机制
**新增触发按钮**：
- 显示位置：初始 Agent 消息下方，作为对话流中的一个卡片
- 按钮文案："✓ 开始概念检验"
- 提示文字："准备好了吗？我会出几道题检验你的理解"
- 禁用条件：文档未加载完成

**点击行为**：
- 前端调用 `POST /api/learning-sessions/{session_id}/trigger-concept-check`
- 后端分析用户提问历史，生成定制化判断题
- 返回 `show_concept_intro` 工具调用
- 前端渲染概念判断卡片

**后端新增端点**：`POST /api/learning-sessions/{session_id}/trigger-concept-check`
- 输入：session_id, user_id
- 处理：
  - 分析用户提问历史，识别可能的薄弱点
  - 生成概念判断题（优先考察用户问过的或易混淆的点）
  - 更新 `session.learning_stage = "concept_check"`
- 输出：工具调用 JSON

#### 2.3 学习阶段状态机
```
documentation_reading (初始阶段；需新增 DB/type/doc 支持)
  ↓ (用户发送消息提问)
concept_qna (主动问答阶段；复用现有阶段)
  ↓ (用户点击"开始概念检验")
concept_check (概念检验中；复用现有 tool UI)
  ↓ (判断错误)
concept_repair (概念修正；复用现有阶段)
  ↓ (判断通过或用户确认练习)
practice_support (可开始练习；复用现有阶段)
```

### 3. 练习反馈布局修复

#### 3.1 问题定位
文件：`aearn/apps/desktop/src/pages/LearningWorkspacePage.tsx`
位置：第 191-197 行

**问题**：`threadMessages` 数组构建逻辑导致 `resumeExerciseMessage` 始终在末尾：
```typescript
const threadMessages = [
  initialMessage,
  ...messages,
  resumeExerciseMessage  // 即使用户已执行练习，仍被注入
]
```

**根因**：
- `resumeExerciseMessage` 的判断条件：`!hasExerciseToolMessage`
- `hasExerciseToolMessage` 只检查 `messages` 中是否有练习工具调用
- 练习执行后的反馈消息是普通文本消息，不是工具调用
- 所以判断条件始终为 true，`resumeExerciseMessage` 持续注入

#### 3.2 解决方案
修改判断条件，增加 `messages.length === 0`：
```typescript
const resumeExerciseMessage: ConversationMessage | null =
  session && session.exercise && !hasExerciseToolMessage && messages.length === 0
    ? { /* 练习卡片 */ }
    : null;
```

**逻辑**：只在用户刚进入、还没有任何对话时才显示练习卡片。一旦用户开始交互（发送消息、运行练习），就不再注入 `resumeExerciseMessage`。

## Acceptance Criteria

### 文档面板
- [ ] 用户进入知识点后，右侧自动展示文档面板
- [ ] 文档包含 5 个标准章节：核心概念、语法结构、实战示例、常见错误、最佳实践
- [ ] 章节可折叠/展开，默认展开前 3 个
- [ ] 有目录导航，点击可跳转到对应章节
- [ ] 用户选中文档文字后，出现"引用到对话"浮层按钮
- [ ] 点击引用后，对话输入框自动填充选中内容
- [ ] 每个代码块有"引用到对话"按钮
- [ ] 文档面板有折叠按钮，可释放对话区空间
- [ ] 文档首次加载时间 < 3 秒
- [ ] 文档生成失败时，显示友好错误提示

### 学习流程
- [ ] 进入知识点后，Agent 发送引导性开场白（告知文档位置、如何提问、如何触发检验）
- [ ] 对话区显示"✓ 开始概念检验"触发按钮
- [ ] 按钮在文档未加载完成时禁用
- [ ] 点击按钮后，Agent 生成概念判断卡片
- [ ] 不再自动显示概念卡片（只在用户主动触发后显示）

### 布局修复
- [ ] 练习卡片显示后，用户执行测试
- [ ] 运行反馈消息显示在练习卡片**下方**
- [ ] 提交反馈消息也显示在练习卡片**下方**
- [ ] 对话流顺序正确：初始消息 → 触发按钮 → 练习卡片 → 用户消息 → 反馈消息

### 边界情况
- [ ] 切换知识点时，文档面板自动更新内容
- [ ] 网络断开时，已加载的文档仍可查看
- [ ] 文档内容缓存 24 小时，重复访问不重新生成

### 复习侧栏一致性
- [ ] 完成第一个知识点学习后，如果后端安排的 `ReviewState.due_at` 仍在未来，左侧「复习」分组可以显示该知识点，但必须是禁用态。
- [ ] 未到期复习项展示明确状态文案或下次复习时间，不显示为可开始复习的 active item。
- [ ] 未到期复习项点击无跳转、无 `POST /api/reviews/start` 请求、无错误 toast；如需反馈，只给本地 tooltip/辅助说明。
- [ ] 左侧「复习」分组中的到期可点击项必须来自与复习页一致的到期队列来源，或至少满足 `due_at <= now()`。
- [ ] 点击左侧「复习」分组中的到期项后，复习页必须展示同一知识点卡片并允许开始复习，不出现「侧栏有可点击项但今日队列为空」的不一致状态。
- [ ] 无到期复习项但存在未到期安排时，左侧可显示禁用项；复习页空态仍明确表示当前没有已到期项。
- [ ] 未到期知识点仍不得绕过后端 `REVIEW_NOT_DUE` 规则开始复习。

## Constraints

- 文档生成使用现有 OpenAI-compatible / Agents SDK 抽象，不写死具体模型名，不引入新的第三方依赖
- 文档面板宽度固定 420px，暂不支持用户调整
- 移动端或小屏幕支持暂不在范围（后续迭代）
- 文档内容只支持动态生成，不支持手动编辑
- 文档内用户标注、搜索功能不在本次范围
- 复习侧栏不得本地伪造 `due_at`、`ReviewState` 或可复习状态；事实来源必须来自后端队列、dashboard 复习计数，或后端返回的 plan/detail 扩展字段。
- 如果当前 `CreatedPlanResponse` 只有知识点 `status` 而没有 `ReviewState.due_at`，实现前需要补齐后端或前端可用的数据来源；不能仅凭 `status` 判断到期。
