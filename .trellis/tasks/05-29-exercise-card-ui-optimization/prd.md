# 优化练习卡片UI直观性

## Goal

重构 ExerciseWorkbench 布局和视觉层次，参考 Flutter 文档风格（暗色代码编辑器 + 清晰分栏 + 即时预览），让用户在练习过程中能快速定位"写代码"和"看结果"两个核心区域，减少认知负担。

## 现状问题

1. **信息层次扁平**：题面、空缺填写、代码区、操作按钮、反馈面板全部线性堆叠在两栏 grid 中，用户需要滚动才能看到运行结果。
2. **操作区过于密集**：运行、提交、提示、解释错误、检查解释等按钮和下拉框混在同一区域，初次使用难以区分主次。
3. **代码区缺乏沉浸感**：浅色背景 + 无明确边界，与周围内容视觉权重相同，不像"编辑器"。
4. **反馈不够即时可见**：运行结果、测试通过/失败状态需要滚动到右栏底部才能看到。

## Requirements

### R1 — 分栏布局重构
- 左栏固定为"编辑区"：题面摘要 + 空缺填写 + 代码编辑器（暗色主题），占主视觉权重
- 右栏为"交互区"：操作按钮 + 运行反馈 + 提示/错误面板，可滚动
- 两栏高度对齐，右栏独立滚动，避免整页滚动

### R2 — 代码编辑器自定义深绿主题
- 注册自定义 Monaco 主题 `aearn-dark`，色板基于项目变量（`--accent: #2f7d63`、`--ink: #15201b`）推导，确保与整体绿色自然系风格协调
- 编辑器区域有明确的圆角边框和阴影，视觉上"凸出"
- 编辑器头部显示语言标签和运行时标签（类似 Flutter 文档的 tab 头）

### R3 — 操作按钮分层
- 主操作（运行测试、提交）突出显示，放在右栏顶部固定位置
- 辅助操作（提示、解释错误、检查解释）收纳为次级区域或折叠面板
- 减少同时可见的按钮数量，降低选择压力

### R4 — 即时反馈可见性
- 运行结果（stdout、测试通过/失败）在右栏顶部主操作下方立即展示
- 测试通过/失败用明确的颜色指示（绿色通过、红色失败）
- 加载状态用骨架屏或 spinner 替代纯文字提示

### R5 — 空缺填写区优化
- 空缺卡片改为内联在代码编辑器上方的紧凑行布局
- 填写后的值实时高亮显示在代码中对应位置（如果技术可行）

## Constraints

- 不改变组件 props 接口和数据流，只重构渲染层和样式
- 保持响应式：≤1180px 时回退为单栏
- 不引入新的 CSS 框架或 UI 库
- Monaco editor 已有 lazy-load 机制，暗色主题切换不需要额外依赖

## Acceptance Criteria

- [ ] ExerciseWorkbench 呈现左右分栏，左栏代码编辑器使用暗色主题
- [ ] 右栏独立滚动，运行反馈在操作按钮正下方可见（无需滚动）
- [ ] 主操作按钮（运行、提交）与辅助操作（提示、解释）视觉分层明确
- [ ] 空缺填写区紧凑排列在编辑器上方
- [ ] ≤1180px 宽度时自动回退为单栏布局
- [ ] 无功能回归：所有现有操作（运行预览、运行测试、提交、提示、解释错误、检查解释）正常工作
- [ ] 暗色编辑器在浅色整体主题中视觉协调，不突兀
