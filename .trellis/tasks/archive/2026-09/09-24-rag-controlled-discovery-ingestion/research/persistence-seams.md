### Minimal proposed write ownership (design recommendation, not existing implementation)

1. **B1 schema writer**: one additive schema fragment plus `aearn/services/api/app/db/schema/__init__.py` and `tests/database/test_schema_manifest.py`; coordinate exact fragment name/manifest and `docs/architecture/database-schema.md` with main/other task owners before writing. Put persistent root/delegation identity and period/cap ceiling, immutable reservation/attempt/settlement or unknown-usage facts, job state/lease generation, discovery receipts, and untrusted candidate identity here. Atomic reserve before provider call across the same root irrespective of query/URL/job/profile; settle actual usage only on authoritative evidence; uncertain spend conservatively holds capacity until reconciliation. Choose constraints/indices and operation idempotency identities to make retries/concurrent first writes safe. A `RagBudgetDelegation.root_id/delegation_id/generation/expires_at` is a reference to validate against current server authority, not a new account balance (`contracts.py:94-110`). Parent explicitly requires budget liaison with item-bank P1/P3 (`phase-ii-implement.md:33`); coordinate the shared budget root/obligation contract before schema freeze.
2. **B1 repository/test writer**: new `aearn/services/api/app/services/grounding/autonomous/{demand_repository,jobs,budget,candidate_repository}.py` (actual factoring can be smaller) and focused offline+PG tests under `tests/grounding/`. Ensure reserve/job creation, lease claim/fencing, provider-attempt receipt and settlement/unknown outcome have transaction boundaries and exact replay; no external call inside DB transaction. Search broker/provider implementation belongs to the other research stream. A policy resolver must resolve trusted actor/action/full demand/purpose/policy generation/current delegation before reservation; application-level gate and DB ledger both fail closed.
3. **B2 staging writer**: additive tables in a *separate B2 fragment if B1 is independently accepted*, appended to the same manifest and expected test tuple by the designated schema owner. New `aearn/services/api/app/services/grounding/autonomous/{staging,provenance,retention}.py` repositories (names tentative) plus focused PG tests. Store bounded candidate/document identities and request-chain/terminal URL, real captured-body scope/hash, version/license/repository revision and lineage, parser/chunk hashes, retention/access status; no secrets/private text in generic receipts. Treat content storage design/permissions separately from immutable small receipts. Candidate staging needs no `grounding_active_corpora` FK/pointer and cannot be read by `hybrid_retrieval.py` or current plan service. Later C performs policy/quality admission and uses the existing corpus repository; no second published-corpus authority.
4. **Classification/docs/test co-ownership**: assign one writer for schema manifest/`test_schema_manifest.py`/schema source-of-truth; B1 then B2 serially append. Update explicit shared classification/inventory checks alongside each new table, with reset/export/cutover non-deletion and private-material non-export. Coordinate with owner of `aearn/services/api/app/services/tutor/cutover.py` if classification expands; do not broaden its exhaustive Tutor namespace blindly. B tests own repository/accounting and staging constraints, corpus baseline owner retains `test_grounding_corpus_repository.py`, `test_grounding_corpus_inventory.py`, and retrieval compatibility regression. No reason for B to edit corpus lifecycle or public DTO in this scope.
