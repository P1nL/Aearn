### 建议最小 default-off 内部链（规划建议，非已实现）

1. 以服务端 snapshot 固定 user/session/current draft_id/version/content_hash、run/input_revision、所有节点目标 hash/Subject/version/facets/purpose。按目的生成 demand；模型所报 source 偏好只是 suggestion。返回内部、版本化 `MaterialSelectionResult`：逐节点 `main_teaching`/`supplementary_explanation`/`assessment_evidence` 的 exact 候选与授权事实、缺口、pending/partial、反馈版本；不要新增默认公开 DTO。
2. 独立 `learning/material_selection.py` 或版本化 `learning/plan_material_binding_v2.py` 做内部门缝，以显式 injected ports 调合格现有 corpus/evidence resolver；default-off 返回 disabled 且零 IO。不能直接把 child05 的 `plan_coverage`/`plan_migration` 接进 `plan_capability.py` 或 `plan_service.py` 的旧默认路径。需要结合 preflight 时用受控注入/内部 adapter 并保留完整节点和依赖的 blocked/gap；部分 ready 不能跳正式 Gate。
3. **确定生产接法：在同一 planning session/conversation 创建下一条持久化 `plan_drafting` run，取得新的 `(run_id, input_revision)` 键（`input_revision` 数值本身不必全局递增），由原 `TutorInteractiveRunDispatcher` → `PlanDraftingProviderGateway` → `PrimaryTutorProviderGateway` → 既有 `learning.plan.draft` capability 产生 successor 草案；不在同一个 run/input_revision 内硬 append 第二稿。**将持久 selection 的安全缩减 gap 反馈经新 run 的内部 context loader 投递，不修改旧默认公开 DTO/另起 provider，也不在 DB 事务内同步模型调用或无限重试。`plan_repository.py:145-168` 对同 `(source_run_id, source_input_revision)` 仅同 hash/facts 允许 replay，否则 conflict；`070_learning_tracks.sql:589-601` 另有唯一约束和同 session predecessor FK；`plan_repository.py:170-179,229-244` 才从当前指针取 parent 并更新 successor/version。服务端建议新增 `MaterialFeedbackRef(selection_handle, expected_parent_draft_id, expected_parent_draft_version, expected_parent_content_hash, expected_session_version)`（内部对象，不让模型/公开 DTO 自报），在新 run 的 context load 前和 `LearningPlanDraftCapabilityHandler.generate()` 的短事务 append 前各做 CAS；handler 构造器可选注入 `material_feedback_consumer: PlanMaterialFeedbackConsumer | None = None`，在 `generate` 内调用 `validate_successor_before_append(run, session, artifact)`，默认 None 零额外 IO。持久 selection 记录新 run 的 allowed scope/一次关联，真实 provider 输出必须作为新 run 证据单列；注入假 provider 仅证明离线契约。
4. **旧 selection handle 只能作为其原 draft/revision/node/goal/purpose 已验证的反馈输入，不能跨 revision 直接冻结 successor。**冻结前必须核 `successor.predecessor_draft_id == selection.parent_draft_id`、新 `draft_version/content_hash` 和完整目标/节点映射；新 run 生成 successor 后，服务端针对 successor 的全部 node/goal hash、`main_teaching`/`supplementary_explanation`/`assessment_evidence` 用途重新选择并重验当前 exact corpus/source/document/chunk revision、授权 generation、claim receipt，签发绑定**新 draft** 的 `successor_selection_handle`，仅此新 handle 可写独立 immutable binding。旧异步回调只可作用于它声称的 parent draft/revision/node/goal/purpose/selection generation，不得覆盖现行 selection 或冻结 successor；变化时失败关闭并显式生成新 selection。评分 `assessment_evidence` 逐 claim 新证据，不继承 `main_teaching` trust。授权检查与 publication fence 由 grounding owner 提供同连接短事务端口；D 隔离 PostgreSQL 证明接口和撤权回滚，题库所有发布入口是 E+题库 owner 范围。
5. 历史 active track、plan revision、progress/assignment/Lesson failures 均不写；新草案仅显式用户确认沿既有路径，旧 active 的修复保持 child05 非激活 proposal。若 binding 是确认前必要条件，新增**版本化内部 opt-in** 确认端口/校验，不悄悄修改旧 confirm 语义。

### 精确结论：parent selection 不可跨 draft 冻结

- **必须使用新持久 run 的新 `(run_id,input_revision)` 键生成 successor**：现有 append_draft 对同键仅允许相同 content_hash/facts 的幂等 replay，不支持同键第二稿；DB 还以 `(source_run_id,source_input_revision)` 唯一约束。新 run 下 append_draft 从当前 session 指针自动记录 `predecessor_draft_id`、递增 `draft_version`，但 D 仍须显式 CAS 校验它等于反馈所属 parent，不可仅依赖“当前”二字（`plan_repository.py:145-179,229-244`；`070_learning_tracks.sql:589-612`）。
- **两次 selection，不跨代复用 handle**：原 parent selection 持久化后只输入下一 run 的受控反馈；新草案产生后服务端针对 successor 全节点/目标重新 selection、核验 current authorization 并签发新 handle；binding 仅接受新 handle + successor 身份。旧异步回调按原 parent/node/用途/代次写入自身状态或被拒绝，不能更新 successor 或其 binding。推荐服务端内部参数 `material_feedback_ref`、`expected_parent_draft_id`/`expected_parent_draft_version`/`expected_parent_content_hash`/`expected_session_version`；冻结方法参数 `expected_successor_draft_id`/`expected_successor_content_hash`/`successor_selection_handle`。`material_feedback_ref` 不放旧公开 capability DTO 或由模型自报。

### 持久化选择

- **当前选定的最小持久化方案（规划，未实现）**：新增两个独立版本化表：`rag_material_selections` 存 immutable selection/feedback 快照、handle、parent draft_id/version/content_hash、session/user、node_key/goal_hash、purpose、demand/report hash、gap/status、source scope/authorization generation、policy version，以及回调的 run/input_revision/幂等范围；`rag_plan_material_bindings` 存 immutable successor draft_id/version/content_hash + predecessor_draft_id、**successor_selection_handle**、node/goal/purpose、exact corpus/registry/retrieval/coverage/source/document/chunk/admission/current authorization/claim receipts 与 binding hash。以 scoped FK/唯一幂等键和同事务 CAS 防串用；parent selection 仅作反馈，新 selection 才能冻 successor。两表不复制原文、不新建 corpus/document/active-plan authority；schema 用新 fragment，不回写 070/260。可给 selection 与 binding 各自 typed repository 方法 `record_selection(...)` / `freeze_for_successor(..., expected_selection_handle, expected_successor_draft_id, expected_successor_content_hash)`，调用前均复查当前用途/授权代次。
- **无新表不是本任务拟采用的交付**：仅内存投影无法跨请求安全保留异步反馈或证明持久冻结；既有 `source_summary_json` 不承载 exact 教材/用途/授权/claim，且改旧 payload/hash 会损害兼容。此备选只保留为边界说明，不作为 D 验收替代。

## Caveats / Not Found

- 写集与新表名均为建议；最终 design 应明确版本化审计例外归属、事务锁顺序由其他代理/owner 合并审查，避免与并行文件冲突。
