## Feasible invocation / required external state

From `aearn/services/api` in the isolated POSIX operator environment, after a newly authorized C capture and independent admission with current pin, current disposable DB and API-created parent/target (see README):

```sh
uv run python ../../infra/rag-d-live/run.py --execute \
  --control-config /root/private/current-control.json \
  --receipt /root/private/current-admission-receipt.json \
  --service-public-key /root/private/pinned-review-service-public.raw \
  --capture-id "$FRESH_CAPTURE_ID" --corpus-id "$NEW_CORPUS_ID" \
  --admission-run-id "$NEW_ADMISSION_RUN_ID" \
  --user-id "$TEST_USER_ID" --session-id "$TEST_SESSION_ID" \
  --conversation-id "$TEST_CONVERSATION_ID" --parent-draft-id "$PARENT_DRAFT_ID" \
  --target-run-id "$TARGET_RUN_ID" --target-input-revision "$TARGET_INPUT_REVISION" \
  --parent-kind real_provider --max-http 8
```

One source GET maximum belongs to the separate C operator stage, not this runner. D has zero source/search calls, <=8 real model HTTP attempts total for this successor (one transport attempt per client invocation, including repairs) and a per-attempt usage/unknown audit. The parent run, if also real, has its **own separately bounded** operator run; this CLI's cap is only for the successor, not a misleading combined parent+successor cap. No automatic retry, public release, item/assessment, or Gate.
