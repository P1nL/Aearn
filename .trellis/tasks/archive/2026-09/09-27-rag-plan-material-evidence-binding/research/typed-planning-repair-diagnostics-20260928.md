# Typed planning repair and safe diagnostics — 2026-09-28

## Concrete root findings

- The observed real-parent checkpoints (`real-chain-parent-protocol-20260928.json`, `real-chain-parent-nothink-20260928.json`) only establish rejected argument/payload protocol and exhausted attempts. They do **not** retain the rejected value or establish that it was an object. There was no new paid provider/DB/source operation in this patch.
- The production JSON client hands an object to `parse_tutor_provider_items`; `TutorProviderItemsEnvelope.model_validate` raises one Pydantic error **per union branch** for an invalid `action.arguments[0].value`. A synthetic object yielded five locations ending in `constrained-str`, `int`, `float`, `bool`, `list[constrained-str]`. Previously the safe issue list consumed its first eight slots on branch errors, while the schema-path diagnostic indexed the **last visited branch** as `array`. Thus “expected array” in logs was an index artifact, not an observation of the rejected value.
- The wire validator `TutorProviderPayloadField._bound_list_value` already enforces `len(json.dumps(value, ensure_ascii=False, separators=(",", ":"))) <= 360`. For a JSON-encoded **string** (`profile_json` or `module_N`), the outer quotes and escapes count. `payload_fields_from_mapping` serializes the accepted string to `TutorPayloadField.value` with the same JSON string representation and its existing 360-character guard; `payload_mapping_from_fields` then decodes it. Boundary tests show 358 raw ASCII characters -> 360 serialized accepted; 359 -> 361 rejected; 180 raw quote characters -> 362 serialized rejected. There is no proven parser/domain limit disagreement to relax. The real ambiguity was guidance saying a string should fit its “advertised maximum length” without identifying the serialized wire boundary. The compact profile/module inner-domain fields can separately have larger per-field limits, but a candidate violating the outer wire limit cannot be silently truncated or widened.

## Patch and safety boundary

- `decision_protocol.py`: collapse duplicate union-branch errors by true wire path, inspect the rejected payload **only for closed JSON type and bounded shape counts**; report character length, serialized length, list count and fixed allowlisted `profile_json`/`module_1..8` key when applicable. Never retain provider values, Pydantic messages, unknown key literals, or body. Repair prompt for a rejected, selected `learning.plan.draft` request is compact and actionable: arguments array, required JSON-encoded string values and the outer serialized 360 limit. Nonplanning teaching/material semantic guidance remains; a pure extra-key error has a small generic repair, preventing unrelated 4K retry overflow.
- `validation_diagnostics.py`: preserve the union root `anyOf` rather than the last array branch. Expose schema-derived allowed JSON types and observed closed type/size fields. Unknown paths remain hashed in logs and become `unknown_field` in the prompt.
- `provider_gateway.py`: activate planning-specific repair only when the rejected action names `learning.plan.draft` **and** the current context advertises that capability. Log only the bounded safe metadata; the existing provider budget check, strict parser, business validator, bounded retries and failure path are unchanged.
- New `tests/tutor/test_tutor_planning_protocol_repair.py`: object versus union expected types, array count/member type, serialized length boundary and escaping, missing title, malicious unknown key/path hashing, accepted string exactness, and invalid replacement remaining rejected.
