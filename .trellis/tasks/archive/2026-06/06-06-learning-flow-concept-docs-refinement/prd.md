# Refine learning flow concept checks and official docs panel

## Goal

收紧 Aearn 学习页的概念检验和右侧文档体验，让用户先看到可信官方资料，再通过少量高价值判断进入代码练习，避免聊天流里出现低价值追问、答案泄露后要求复述、以及过重的判断结果卡片。

本任务只处理学习页当前知识点流程，不重新设计 onboarding 路线生成、不扩展复习调度、不重做整体 AppShell。

## User Problems

- 右侧文档当前更像 Agent 讲义，按多个教学小节压缩/重组；用户希望它作为可信资料区，直接承载知识点对应的官方文档内容和实例。
- `show_concept_check_result` 独立大卡占用聊天纵向空间，反馈内容本质是轻量诊断，不需要以大卡重复展示。
- `unclear` 判断边界过宽，模型会把部分正确、漏答或已足够回答的问题继续追问。
- 概念追问轮数没有覆盖所有模糊路径；`unclear` 可以反复出现。
- 模型会在解释中泄露下一轮要检查的答案，例如先写出 `65.0`，再要求用户回答 `A` 转成 `double` 后的值，导致用户只需复述答案。

## Requirements

### 1. Official documentation panel

- 右侧文档改为两个主区块：
  - `官方文档内容`：当前知识点对应的官方/可信文档片段，翻译成用户当前学习界面语言。
  - `实例`：与当前知识点直接相关的示例。
- 不再把右侧文档拆成 `核心概念`、`语法结构`、`实战示例`、`常见错误`、`最佳实践` 等五段式教学小节。
- 不使用 AI 对官方文档做压缩、改写或重新组织；允许做忠实翻译、格式清理、术语一致化和代码块保留。
- 如果官方已有用户语言版本，优先引用官方本地化页面；没有本地化版本时，只翻译当前知识点所需的最小片段。
- 文档区必须保留来源标题、URL、抓取/生成时间和可查看原文的入口。
- 实例必须标明来源：
  - `官方示例`：来自官方/可信文档。
  - `Aearn 示例`：由 Aearn 为当前练习补充，不得伪装成官方内容。
- 不缓存或展示超出当前知识点需要的大段整篇官方文档；范围必须是可追溯的目标片段。

### 2. Concept check result UI

- 前端不再把每次 `show_concept_check_result` 渲染成独立大卡。
- 判断结果仍保留为后端 tool event / persisted message metadata，用于刷新恢复、状态机和测试。
- UI 应把判断反馈压缩为普通 Agent 回复中的紧凑反馈，或轻量 inline status：
  - `判断`
  - `原因`
  - `下一步`
- 如果存在 `repair_check` 或 `actions`，只展示必要 quick replies / action buttons，不重复展示大面积卡片。

### 3. Concept judgement semantics

- `unclear` 只用于以下情况：
  - 用户没有回答当前题目或只说“不知道/随便/不确定”。
  - 用户回答与当前题目无关。
  - 用户自然语言立场无法判断。
  - 用户同时表达互相冲突的判断。
- 用户漏选、多选题只答对一部分、理由不完整但方向明确时，不应判为 `unclear`；应按 `incorrect` 或等价的 incomplete feedback 处理，并指出缺失点。
- 用户已经答中核心规则时，不得因为没有说出额外具体数值而无限追问；最多换一个迁移题验证。
- 概念追问总轮数必须覆盖 `incorrect` 和 `unclear` 两类路径；达到上限后进入以下之一：
  - 引导练习。
  - 再看一个例子。
  - 明确跳过概念检验进入练习，并标记 `learning_incomplete=true`。

### 4. Answer leakage prevention

- 同一轮输出中，如果 `next_prompt` 要求用户给出某个具体值、选项或代码片段，则 `explanation` 和卡片正文不得包含该目标答案。
- 如果 `explanation` 已经给出目标答案，则 `next_prompt` 不得要求用户复述同一个答案。
- 答案已泄露时，只允许：
  - 判定当前概念通过并进入练习。
  - 给一个迁移题，例如从 `'A'` 换到 `'B'`。
  - 要求用户解释原因，而不是复述数值/选项。
- 该规则应由 Agent 输出契约和自检字段保护；后端不写死具体答案、不用规则改写教学内容，只做结构校验和持久化。

## Acceptance Criteria

- [ ] 右侧文档面板只展示 `官方文档内容` 和 `实例` 两个主区块。
- [ ] 官方文档内容保留来源标题、URL、时间和原文入口；内容为官方本地化版本或忠实翻译片段，不是 AI 压缩讲义。
- [ ] 示例区能区分 `官方示例` 与 `Aearn 示例`。
- [ ] `show_concept_check_result` 不再以前端独立大卡展示；刷新恢复后也不恢复为大卡。
- [ ] 判断反馈以紧凑形式展示，仍能看到判断结果、原因和下一步动作。
- [ ] `unclear` 的 prompt、后端策略和测试覆盖明确边界：部分正确/漏答不再被当成 unclear。
- [ ] `incorrect` 与 `unclear` 都纳入概念追问上限；达到上限后不再继续“更具体一点”追问。
- [ ] 测试覆盖 Agent 输出契约：最终 `explanation` 已泄露目标答案时，最终 `next_prompt` 不能要求复述同一答案。
- [ ] 测试覆盖截图场景：用户已回答“是该字符的 Unicode 数值”后，模型不能先给出 `65.0` 再要求用户回答 `65`。
- [ ] 文档、API contract、前端交互规格与实际行为一致。

## Out of Scope

- 不做整站多语言系统；本任务只要求文档面板按当前用户学习界面语言展示。
- 不实现通用网页翻译器或全文官方文档镜像。
- 不更改 FSRS 评分、复习调度和练习提交评分。
- 不重构 onboarding 动态路线生成，只在需要时消费其已有来源字段。
- 不删除后端 `show_concept_check_result` tool event；只改变展示方式和判断策略。

## Open Questions

- None blocking. 推荐实现策略见 `design.md`：先支持中文界面下的官方片段忠实翻译/来源归因，再为未来多语言 UI 留出字段边界。
