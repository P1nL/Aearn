# 技术设计

## 总体边界

保留现有顶层结构，只在所属层内部做渐进式模块化。父任务不直接修改产品代码，通过四个有序子任务控制风险和验证范围。

## 子任务拓扑

```text
仓库治理与卫生优化
  -> Desktop 前端模块化
  -> API 持久化与测试模块化
  -> 数据库 Schema 模块化
  -> 全量集成审计
```

第一阶段先修复规范、文档和工具状态，使后续实现依据可信；前端和后端分别实施，避免跨层大爆炸；Schema 最后处理，因为其验证依赖完整后端测试。

## 兼容策略

- 前端使用兼容 barrel 保持现有 import，逐步迁移域模块。
- 后端保持 `app.services.tutor.persistence` 公开导入路径，内部改为 package/facade 与 transaction-bound mixin 或组件。
- Schema loader 保持同一连接、同一事务和确定顺序，不允许按文件系统自然顺序隐式执行。
- 测试目录移动时保留共享 support 的稳定导入入口。

## 回滚

每个子任务独立修改并验证。若某阶段失败，只回滚该阶段新增结构，不撤销进入任务前已有的用户修改。父任务不要求 Git commit 作为完成条件。
