# Aearn 第一版 release 收口

## Goal

确认当前 Aearn 第一版是否已经达到可发布状态，并把这次发布前收口落成可审查的证据链：自动化验证结果、手工 smoke 结论、阻塞项处理结果、已知问题边界，以及必要的文档回写。

## Confirmed Facts

- `docs/plans/learning-agent-implementation-plan.md` 已把第一版正式里程碑定义为 `M0` 到 `M6`，其中 `M6` 明确包含发布前审查、测试报告和文档回写。
- `docs/qa/acceptance-test-plan.md` 已定义发布门禁：
  - `P0` 必须全部通过；
  - `P1` 通过率不低于 95%，且前端手工 QA 的 `P1` 问题要么修复，要么写入已知问题清单；
  - `P2` 允许作为非阻塞项被记录。
- 当前仓库没有单独的 release doc；现有 source of truth 仍是实施计划、验收计划和 Trellis task / journal 记录。
- 当前 `main` 分支工作树干净，且 Trellis 中没有其他 active task。
- `05-17-m6-settings-resume-hardening` 已完成并归档，因此这次任务不再实现 M6 主功能，而是做第一版整体 release 收口。

## Requirements

- 以现有 source of truth 为准，不扩展到第二版功能或新的产品范围。
- 重新核对第一版主闭环是否满足发布门禁，至少覆盖：
  - onboarding / plan 确认；
  - 学习闭环；
  - 复习闭环；
  - 笔记流；
  - 恢复学习与设置页边界。
- 运行与第一版发布直接相关的自动化验证，并记录结果。
- 对仍需人工判断的桌面端关键路径补一次最小 smoke，避免只靠单元测试宣布发布完成。
- 若发现 `P0` 或 `P1` 阻塞项：
  - `P0` 必须修复并重跑验证，不能带病发布；
  - `P1` 优先修复；若不修复，必须明确写入已知问题清单，并说明为何仍可发布或为何需要阻塞。
- 若实现与文档存在未解释偏差，必须把偏差回写到最接近的 source-of-truth 文档，而不是只留在任务说明里。
- release 收口结束时，必须能给出清晰结论：
  - `ready to release`；
  - 或 `not ready`，并列出阻塞项。

## Out of Scope

- 新增第一版计划外功能。
- 重新设计评分规则、FSRS 规则、Attempt 内部模型或运行时能力边界。
- 启动第二版路线图、账号系统、远程同步或其他未在第一版计划中的扩展。

## Acceptance Criteria

- [ ] 第一版 release gate 的核对范围和结论已形成明确记录，而不是口头判断。
- [ ] 所有 `P0` 发布门禁都已通过，或若存在失败项，已被修复并附带重跑证据。
- [ ] `P1` 状态清晰：要么达到通过门槛，要么每个剩余问题都有已知问题记录和发布决策说明。
- [ ] `P2` 项已完成分流，不再混入 `P0/P1` 发布结论。
- [ ] 若发现 contract / 文档偏差，相关 source-of-truth 文档已同步更新。
- [ ] 任务结束时可以给出明确的 `ready / not ready` 发布结论，并说明理由。

## Open Questions

- 当前无必须先问用户的产品决策问题；默认按现有发布门禁执行，并以“先验证、再修阻塞、最后下结论”为本任务策略。
